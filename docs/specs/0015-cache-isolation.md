# Spec 0015: Cache isolation — product entitlements and key "forget" on the invalidation bus (cross-tenant suite, layer 5)

**Status:** **Accepted (2026-10-13)** by the owner, after review of revisions 1 and 2 (#65). D1 (no acknowledgements) and D2 (keep the 1-hour TTL) are decided. Acceptance added two CI7 edge-case tests (an unwrap finishing after the full TTL; old callbacks meeting a replacement load) and corrected the TTL reference to E5.
**Phase:** 0. It closes the "Cache isolation" item of [docs/18](../18-roadmap.md): product-cache invalidation (spec 0003 P7) and key-forget propagation (spec 0006). That completes layer 5 of [docs/12 §3](../12-testing-strategy.md) for today's caches.
**Builds on:**

- [spec 0003](0003-product-entitlements.md) P7: the products cache;
- [spec 0006](0006-envelope-encryption.md): the keyring cache (E5/E6) and the destruction boundary;

## Why

Three per-instance caches hold tenant-scoped, security-relevant state. Today only the instance that made a change evicts anything, and only for one of them.

| Cache                             | Holds                        | Today                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Risk                                                                                                                                                   |
| --------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ProductService` (API and worker) | the tenant's active products | The changing instance evicts locally; others converge within the TTL (30 s). **No generation guard:** a read that began before the eviction can re-cache the old set. Its expiry is computed from the read's **start**, so a stale re-cache lasts at most one TTL from that start.                                                                                                                                                                                           | A disabled product stays usable on other instances for up to 30 s, and briefly on the changing instance itself through the re-cache race.              |
| `TenantKeyring` (API and worker)  | **unwrapped DEKs**           | `forget(tenantId)` exists, but **nothing calls it**. Key destruction runs in the `keys` CLI, a separate process. Three more defects, from the owner's reproduction:<br>• **The load race:** a pending unwrap that finishes after `forget()` re-caches the key, and `key()` returns it again.<br>• **Expiry only on lookup:** an idle expired key stays cached and un-zeroed.<br>• **The deadline restarts:** expiry is computed after the unwrap, so a slow load extends it. | After crypto-shredding, running processes keep decrypting with the destroyed key for up to **1 h** (the E5 TTL), and possibly longer through the race. |
| `TenantResolver` (API)            | host → tenant, and status    | No writer exists in the app; tenants change only via seed or DB.                                                                                                                                                                                                                                                                                                                                                                                                             | None today. A future writer (the console) must not ship without invalidation.                                                                          |

OWASP's multi-tenant guidance treats cache invalidation as part of tenant isolation (spec 0007 §Why). This spec puts the products and keys caches on the bus, closes the keyring's own races, and binds the future writers.

## Decisions (owner, 2026-10-13)

- **D1: no acknowledgements.** Pub/sub has no delivery receipt. The CLI reports what it knows (CI6), never that subscribers forgot.
- **D2: keep the keyring's 1-hour TTL** as the lost-message bound, consistent with spec 0006's destruction boundary. It will be revisited with the shred ledger.

## Design

- **One small bus helper, `InvalidationBus`:**
  - publishes after commit, with a bounded attempt (CI6), and never throws;
  - one dedicated subscriber connection per process, which never blocks startup;
  - zod parsing per channel.
  - Products and keys use it. **Settings stay as built in spec 0007,** and can move onto the helper later with no behaviour change.
- **Products:** the cache gains a per-tenant generation; `setEnabled` publishes in its `finally`, so the compensated path is covered; the outbox worker subscribes too, because it checks products (B10).
- **Keys:**
  - **The CLI** connects to Valkey only to publish. It never subscribes, and never needs the API.
  - **Forgetting a tenant drops every version, cached and in flight.** The next decrypt unwraps the live versions again (one Vault call each); destroyed versions fail.
  - **The keyring's guard** follows CI7: a generation recorded at load start and checked before caching; the deadline set at load start; a timer per entry that zeroes on expiry; zeroing on every discard.
- **Valkey trust:** as in spec 0007, Valkey is trusted infrastructure on the private network. A forged message can only cause an extra eviction (a cache miss), never a wrong value, which is why messages carry no values.

## Out of scope

- Acknowledgements (D1).
- Shortening the 1-hour bound (D2), and the shred ledger and restore safety (docs/18, backups item).
- The tenant resolver's own broadcast until its first writer exists, and an entitlement writer: CI10 binds both.
- Moving settings onto the helper.
